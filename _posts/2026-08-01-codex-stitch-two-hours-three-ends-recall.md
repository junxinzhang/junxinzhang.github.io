最近做了一件很土、但很能说明问题的事。

产品召回相关的三端——**H5、小程序、管理后台**——我用 **Codex + Google Stitch**，大约 **两小时** 交了可演示、可继续硬化的初版。

不是「生成了几个静态页面截图」，是把主流程页面、后台管理骨架、多端一致的信息架构拉通；后面该接的接口、权限、审计再按企业节奏补。

五月我写过 [一个人的 AI 军团](/ai-one-person-army-full-delivery-sequoia-agi)：从售前到运维，一个人顶一个 Team。那是**项目全链路**。今天这篇更窄，只钉交付里最容易被低估的一段：

> **界面与三端实现，曾经是分工最碎、等待最长的一截；现在可以被同一条 AI 链路压进小时级。**

## 一、先把账摊开：过去三端为什么慢

产品召回不是炫技场景。它通常要同时面对三类人：

| 端 | 谁在用 | 典型页面 |
|----|--------|----------|
| **H5** | 消费者 / 渠道扫码 | 查询批次、确认召回范围、指引与登记 |
| **小程序** | 同一批用户，微信生态里 | 与 H5 同构的查询与进度，偏轻量入口 |
| **管理后台** | 运营 / 质检 / 客服 | 批次配置、范围发布、进度看板、导出与处置 |

传统路径很熟悉：

1. 产品经理写需求与流程图  
2. UI 出多端稿，评审两轮  
3. H5 前端开干  
4. 小程序另一套工程再开干  
5. 管理后台再开一条  
6. 联调、改交互、补权限  

就算人齐、需求清楚，**「看起来像能演示」**也常是按**天到周**计。慢不在某一行代码，而在**等待**：等稿、等排期、等三端对齐、等改完再改。

两小时交三端，不是证明「召回业务变简单了」，而是证明：

**设计与实现之间的那堵墙，被工具链凿开了。**

## 二、我实际怎么跑：Stitch 定界面，Codex 落代码

工具分工很简单，不造概念。

### 1）Google Stitch：先把「长什么样、怎么点」钉住

[Google Stitch](https://stitch.withgoogle.com/) 是 Google Labs 的 AI UI 设计产品：用自然语言 / 画布把想法拉成高保真界面，再在 AI-native 画布上迭代多屏。对缺专职设计师、又要快速对齐产品感觉的人，它的价值很直接——

**先把信息架构和多端页面定下来，再进代码。**

这次我在 Stitch 里并行拉了两组画布（项目链接对内使用，文中不贴客户名与内部 ID）：一端偏**用户侧**（H5 / 小程序气质的查询与指引），一端偏**管理侧**（批次、范围、进度、处置）。

用户侧主路径，在画布上一屏就能看完：

![Stitch 用户侧召回主路径多屏](/assets/images/screenshot-20260801-stitch-recall-user-flow.webp)
<!-- 截图来源：Stitch 用户侧画布导出；演示数据，敏感字段已打码/示意 -->

从左到右大致是：

1. **召回首页**——通知、范围、办理步骤  
2. **罐底码 / 批次验证**——在范围内才继续  
3. **购买证明上传**  
4. **申请信息填写**（联系人、收款、退款金额）  
5. **核对并提交**  
6. **提交成功**  
7. **进度详情 / 补材料 / 退款完成**

串起来就是：

| 模块 | 干什么 |
|------|--------|
| **工作台** | 今日新增、待办、紧急事项、近期处理记录 |
| **申请列表 / 资料核验** | 消费申请排队、产品与购买证明核对、时间线 |
| **物流 / 仓库** | 取件承运、仓内质检、不合格原因 |
| **退款处理** | 授权金额、线下到账登记、凭证与审计 |
| **召回活动设置** | 活动周期、批次名单、物流伙伴、权限策略 |

用户侧负责「申请人走完主路径」；管理侧负责「运营把单接住、核完、退完」。  
不在 CSS 里开产品会，是这两小时能成立的前提。

### 2）Codex：按画布与约束把三端骨架写出来

界面方向定了之后，把约束写清楚交给 Codex：

- 三端信息架构一致，组件可复用处尽量复用  
- 先打通主路径，别一上来堆动画和边角  
- 管理后台预留权限、列表、详情、导出位  
- 业务文案与合规提示可配置，不写死在组件里  

Codex 负责的是**实现带宽**：页面、路由、状态、表单校验骨架、后台 CRUD 壳子。我负责的是**边界与验收**：哪些字段必须有、哪些动作不能自动、什么叫「这版能交」。

落到小程序 / H5 容器里，第一步往往就是「登记退货产品 + 验证批次」——设计稿上的节点，变成可点的表单：

## 三、两小时交了什么，没交什么

必须把话说死，不然「两小时」会变成标题党。

### 交了的

- 用户侧主路径：查询 → 范围判断 → 指引 / 登记的页面闭环  
- 小程序与 H5 同构的信息架构（入口与容器不同，业务步骤对齐）  
- 管理后台：批次与范围配置、列表与详情骨架、进度与导出位  
- 多端视觉与组件节奏基本一致，能演示、能截图、能拉评审  

### 没交、也不该假装两小时交完的

| 项 | 为什么还要人 / 时间 |
|----|---------------------|
| 真实接口与主数据 | 批次、渠道、序列号规则在业务系统里 |
| 权限、审计、操作留痕 | 召回场景对「谁改过什么」敏感 |
| 合规文案与法务口径 | 对外话术不能靠模型自由发挥 |
| 灰度、监控、回滚 | 企业上线标准，不是 Demo 标准 |
| 异常与边界 | 查无批次、跨渠道、重复登记…… |

所以更准确的表述是：

**两小时交付的是「企业级开发与交付的前端与管理骨架」——能进联调、能进评审、能当真实项目的 Day 0。**  
不是「两小时零风险全量上线」。

五月那篇写的是全链路一人交付；这篇补的是：**交付链里最碎的一段，也被压进了小时级。** 两者叠在一起，才是「企业级」四个字在 2026 年的新含义——不是堆人头，是**把可硬化的骨架先立住**。

## 四、50 倍杠杆：怎么算，算在哪

我说「程序员的杠杆被放大了大约 50 倍」，不是实验室秒表，是**交付体感的数量级**。

粗账可以这样摊：

| 传统粗算（小团队、需求相对清楚） | 量级 |
|----------------------------------|------|
| UI 多端稿 + 两轮小改 | 1–3 人日 |
| H5 主路径 | 2–4 人日 |
| 小程序同构实现 | 2–4 人日 |
| 管理后台骨架 | 3–5 人日 |
| 对齐与返工缓冲 | 2–3 人日 |
| **合计** | **约 10–20 人日** |

一人日按 8 小时，就是 **80–160 小时**量级。  
压到 **约 2 小时** 可见交付，倍率落在 **40–80 倍** 区间；我说 50 倍，取的是中间、且偏保守的体感。

注意三个限定：

1. **比的是「可见三端骨架」**，不是含全部联调与合规的终态上线  
2. **前提是边界清楚**——召回主路径本身不复杂，复杂在数据和责任  
3. **杠杆落在会拆问题、会写约束、会验收的人身上**；不会拆的人，只会更快堆技术债  

六月写过 [AI 是普通人这辈子最大的杠杆](/ai-biggest-leverage-frontier-intelligence-scarcity)：最高级智能真正用满的人极少。这篇落到工程现场，就是同一句话的施工版——

> **杠杆不在「会不会打开 Codex」，在「敢不敢把三端交付的目标、约束、验收写清楚，然后让工具链连续跑完」。**

## 五、企业级交付，到底多出来哪一层

很多人听完「两小时三端」，第一反应是：那还要架构师、测试、项目经理干什么？

要。而且更要。

因为压缩掉的是**绘图与写样板的时间**，不是**责任**。

企业级和玩具项目的差别，从来不在「页面好不好看」，而在：

1. **边界**：哪些自动，哪些必须人点确认  
2. **数据**：批次、渠道、序列号以谁为准  
3. **权限**：谁能扩召回范围，谁只能看  
4. **审计**：出了事能否回放  
5. **口径**：对外文案谁签字  

AI 把「做出来」变便宜了，于是「做对没有」反而更贵——  
错得更快，也传得更广。这和我在 [从 PE 到 Graph](/pe-context-harness-loop-graph-evolution) 里说的「失败变贵，杠杆外移」是同一逻辑：  
**工具越强，人越要站在验收和责任一侧，而不是和模型比手速。**

所以我自己的工作流，现在更像：

1. 先写清：用户是谁、主路径三步是什么、后台最少管什么  
2. Stitch 出多端界面，当场改信息架构  
3. Codex 按约束落三端骨架  
4. 我按清单验收：主路径、空态、权限位、文案位  
5. 再进真实接口、合规与上线清单  

两小时省下的，是第 2–3 步里过去最磨人的等待。  
第 1、4、5 步，仍然是人的护城河。

## 写在最后

压成五句：

1. **产品召回三端（H5 + 小程序 + 管理后台），我用 Codex + Stitch 大约两小时交了可演示初版**  
2. **慢通常慢在等待与三端对齐，不在某一行业务代码**  
3. **Stitch 管「长什么样」，Codex 管「跑得起来」，人管「该不该、算不算交」**  
4. **相对传统 10–20 人日量级的可见交付，体感杠杆大约 50 倍——比的是骨架，不是零风险终态**  
5. **企业级多出来的是边界、数据、权限、审计、口径；这些更需要人**

土话一句：

**程序员的杠杆被放大，不是因为人变成了打字机，而是因为设计和实现终于能被同一条链路连续推动。**

再补一句更硬的：

**两小时能交骨架，不能交责任。谁签字、谁背锅、谁对用户说那句召回说明，仍然是人。**
